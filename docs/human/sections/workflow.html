Gate 2 — needs-human (can fire from any stage)

Any agent that hits genuine ambiguity — unclear spec, architectural fork, missing context — adds the needs-human label, assigns Kimmo, and stops. Kimmo resolves the blocker and puts the issue back into the lane. This is the pressure-release valve that prevents compounding errors. Direction and pivot decisions are never delegated.

🔀

Merge policy — Marcy merges in-session after review, manual testing decoupled

A PR merges without waiting for a human when both hold: Marcy approved with no Critical/Major findings, and CI is green (coverage floor + patch-coverage gate). There's no GitHub-native auto-merge or branch protection on this repo (private, free plan) to do this on its own, so Marcy merges the PR herself (gh pr merge --merge, a regular merge commit) the moment she confirms both conditions — same pass that sets the Linear issue to Completed, not a separate step. Manual testing no longer gates the merge — even changes that want a device/simulator run or a visual/UX eye merge on review + CI. That verification is logged instead: the developer appends a case to the Manual Test Checklist (steps → expected, plus an "automate?" note), and Kimmo verifies in batches on device, ticking cases off (git-tracked). A failed case becomes a new bug ticket, not a merge block. The only thing that still holds a PR open is needs-human (Gate 2).

Path to autonomy

The current pilot requires Kimmo to manually dispatch agents and hold two gates. This table shows each manual step, its current state, and what would need to be true to automate it.

Step Now Status What unlocks automation
Triage / pick items Kimmo reads Backlog and points Shirley at items Manual A priority-scoring agent or scheduled sweep; requires Kimmo to trust the selection criteria enough to not review every pick
Gate 1 — spec approval Kimmo reads spec and moves to Todo Manual — intentional Not designed to be automated. Direction is a human decision. Keep this gate.
Dispatch Randy to Todo Kimmo tells Randy which issue to work Automatable Scheduled agent or GitHub Action that reads Linear for Todo issues and dispatches Randy. Works once Randy is trusted end-to-end.
Diagnose CI failures Randy blocks on the PR's CI run in-session (gh run watch --exit-status) right after opening it Automated ✓ In-session, not a GitHub Action: on a red build Randy pulls the logs, reproduces locally first (./gradlew buildAndroidOnly / ./gradlew :composeApp:testDebugUnitTest) so each push is already expected to pass, fixes, commits with an [auto-fix] marker, pushes, and re-watches — bounded to 2 attempts, then needs-human + Kimmo. Only covers the run Randy just triggered, not overnight/third-party failures. The .github/workflows/ci-failure.yml Action is parked at workflow_dispatch only (cost decision); restore its workflow_run trigger for unattended coverage.
Dispatch Marcy on PR open Randy invokes Marcy directly (Task tool) as his last step, right after adding in-review Automated ✓ In-session Randy→Marcy handover, not a GitHub Action. Marcy reviews against AC/DoD/MV* rules, updates Linear labels/status herself, and Randy relays her verdict. Review + CI green → the PR merges (manual testing is logged, not gated — see Merge policy). The .github/workflows/code-review.yml Action is parked at workflow_dispatch only (cost decision); restore its pull_request trigger to re-enable CI-side review.
Dispatch Seppo / Mr.T Kimmo decides when to invoke manually Automatable Marcy's review output could tag PRs that need deeper QA or UI review, triggering the relevant agent automatically.
Gate 2 — needs-human resolution Kimmo resolves the blocker and re-dispatches Manual — intentional Not designed to be automated. Ambiguity and architectural forks require judgment. Keep this gate.
Merge PR to develop Marcy runs gh pr merge herself on pass + CI green Automated ✓ Review + CI are the gate, but nothing merges on its own — no GitHub auto-merge or branch protection exists on this repo (private, free plan), so Marcy executes the merge in-session as part of her review pass. Manual testing is decoupled — behaviour needing a device/UX check is logged to the Test Checklist and verified async, not before merge. Only needs-human (Gate 2) holds a PR open.
Dispatch doc-agent post-merge Claude Code cron job runs Phill Tue–Sat at 09:07 Automated ✓ Runs inside Claude Code (Pro subscription, no API token cost) — not a GitHub Action. Checks Linear for tickets moved to Done in the last 24h, finds the merge commit on develop, and opens a docs PR. Exits cleanly if nothing completed. The .github/workflows/doc-agent.yml Action is parked at workflow_dispatch only (no longer triggers on push).

Recommended automation sequence

  1. DoneDoc sweep — Phill now runs on a Claude Code cron (Tue–Sat 09:07), no GitHub Action needed.
  2. DoneMarcy on PR open — in-session Randy→Marcy handover, no GitHub Action needed.
  3. DoneCI auto-fix — in-session blocking watch by Randy, bounded to 2 attempts.
  4. Once Randy is trusted end-to-end, automate Randy dispatch from Todo (scheduled sweep or GitHub Action).
  5. Add Seppo/Mr.T auto-trigger based on Marcy's review tags.
  6. Keep Gate 1 and Gate 2 permanently manual. (Merge is now automated on review + CI; manual testing is decoupled to the Test Checklist and verified async.)

The corresponding GitHub Actions workflows (code-review.yml, doc-agent.yml, ci-failure.yml) are retained for manual workflow_dispatch runs but parked from auto-triggering — a cost decision (free-plan Actions minutes), not a quality one.
