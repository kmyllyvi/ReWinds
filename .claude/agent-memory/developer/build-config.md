# Build configuration gotchas

## Gradle configuration cache is enabled globally
`gradle.properties` sets `org.gradle.configuration-cache=true`. This means any
custom Gradle task must be **configuration-cache compatible**:
- Do NOT access `Task.project` (or `project.*`) inside `doLast` / `doFirst`.
- Do NOT call `Project.exec { }` at execution time.
- Capture inputs (dirs, files, properties) into local `val`s at configuration time.
- For running external processes at execution time, inject
  `project.serviceOf<org.gradle.process.ExecOperations>()` at config time and call
  `execOps.exec { }` in `doLast`.
- Import: `import org.gradle.kotlin.dsl.support.serviceOf`

### CI symptom
CI step "Generate coverage report" (`./gradlew :composeApp:coverageReport
-PenableCoverage=true`) failed with "Configuration cache problems found" even
though all unit tests passed. The failing task was `coverageReport` in
`composeApp/build.gradle.kts`. Fixed in commit 0631168 (KIM-273 branch).

## CI runs coverageReport, not just testDebugUnitTest
`.github/workflows/ci.yml` line ~41 runs:
`./gradlew :composeApp:coverageReport -PincludeAllTargets=false -PenableCoverage=true --no-daemon`
So a green local `testDebugUnitTest` is NOT sufficient to prove CI passes —
also run the coverageReport command locally to reproduce CI.

## docs/coverage/detailed.html is a generated artifact
Regenerated by `generate_coverage_metrics.py` on every coverage run. Its diff is
usually just a timestamp — revert it before committing unless intentionally
updating coverage docs.
