- `composeApp/src/commonMain/kotlin/settings/SettingsView.kt:289` — private `ApiKeyDialog` composable, **shared** between the Anthropic key and Visual Crossing key entries in Settings (`SettingsDialog.ANTHROPIC_KEY` / `SettingsDialog.WEATHER_KEY` at lines ~242/259). Any copy change to one key's description/urlHint strings should be checked against the other for tone/length parity, since users see both from the same list one tap apart. `description` and `urlHint` `Text` composables have no `maxLines` cap; `AlertDialog`'s text slot scrolls on overflow — so copy-length changes here are low truncation risk, wrapping/scrolling only.
  - As of KIM-252, `AnthropicKeyDialog` (SettingsView.kt:366) is now a **separate, parallel** composable (not reusing generic `ApiKeyDialog`) because it needs richer state: inline empty-validation error, save-success confirmation, and a tappable "get an API key" link. It duplicates most of `ApiKeyDialog`'s layout by hand rather than extending it — acceptable for now but worth watching for drift if a third key type is ever added (extract a shared "key entry body" composable at that point).
  - Pricing/free-tier transparency parity gap: `visualCrossingKeyDescription` (KIM-279) explicitly states the free tier limits ("1,000 records per day... no credit card required"). `anthropicKeyDescription` (KIM-252) says nothing about Anthropic API pricing being pay-as-you-go/metered (no free tier). Since both dialogs are one tap apart in the same Settings list, a user could reasonably assume both are free. Flagged as a Minor/Medium copy gap in KIM-252 review — worth a follow-up ticket rather than blocking, since the ticket AC doesn't require pricing disclosure.

- `composeApp/src/commonMain/kotlin/onboarding/VcKeyOnboardingScreen.kt` — despite string names like `vcKeyNudgeBody`/`vcKeyNudgeTitle` suggesting a small dismissible "nudge banner," this is actually a **full-screen, blocking, no-dismiss onboarding gate** (see file's own doc comment, referencing KIM-309) routed at `core/Router.kt:116`, shown on every launch until a valid VC key is configured. Center-aligned, 32dp horizontal padding, generous vertical spacing — plenty of room for multi-sentence body copy, low wrapping risk. Correctly uses `IsobarBackground` rather than `.background()` per project convention.

- `composeApp/src/commonMain/kotlin/ui/components/KeyNudgeBanner.kt` (added KIM-252) — reusable **inline, non-blocking, dismissible-by-nature** (just disappears once key is saved) nudge banner, distinct from the VC onboarding gate above. Row layout: info icon + title/body column (weight 1f) + trailing action label text, `surfaceRaised` background, whole row is `.clickable`. Used in `ai/ChatView.kt` (below `AppHeader`/`PlaceTagPill`, above the `LazyColumn` message list), gated on `uiState.showClaudeKeyNudge` (derived in `ChatViewModel.refreshClaudeKeyNudge()` from `apiKeyChecker.isAnthropicKeyConfigured()`, called on init — verify navigation back into Chat re-triggers it if that matters for a future review).
  - Gotcha found in KIM-252 PR #70: `TestTags.CHAT_CLAUDE_KEY_NUDGE_ACTION` is declared in `TestTags.kt` but never actually applied to the action-label `Text` in `KeyNudgeBanner.kt` — only the outer container gets `CHAT_CLAUDE_KEY_NUDGE`. Dead test tag / no isolated tap target for the action text specifically (whole row is clickable so it still works, just not independently testable/inspectable).
  - Redundant messaging gotcha: `ChatView.kt` also still has a **separate modal** `AlertDialog` (`uiState.showApiKeyMissingDialog`, shown on send-attempt with no key, text = `apiKeyNotConfiguredMessage`) that duplicates what the always-visible `KeyNudgeBanner` already says. Both can't be dismissed independently of the key actually being saved — check this doesn't double-nag in the same session in future reviews.

- Copy tone convention confirmed by KIM-252: AC explicitly bans "token" jargon and requires "API key" throughout. Both EN and DE strings for KIM-252 (`claudeKeyNudge*`, `apiKeyEmptyError`, `apiKeySaved`, `anthropicKeyDescription`, `anthropicApiUrl`/`anthropicApiLinkLabel`) consistently say "API key" / "API-Schlüssel" — no "token" anywhere. Good precedent to check against in future key-related copy.

**How to apply:** When reviewing AppStrings.kt copy changes tied to these composables, always (1) check the sibling dialog/screen for tone consistency, (2) don't assume "banner" naming means small/space-constrained — verify by reading the actual composable, (3) check for redundant/duplicate user-facing messaging when a ticket adds a new inline nudge alongside existing modal dialogs for the same missing-key condition.
